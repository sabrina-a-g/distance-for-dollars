The Strava Handshake

How DistanceForDollars, your browser, and Strava pass a token around so the app can read your activities without ever touching your Strava password. Built together while we scope the OAuth work — the open pieces at the bottom are still genuinely open.

Connecting an account (happens once)

This is the part that needs a human in the loop — someone clicking “Connect Strava” and approving on Strava’s own site. It ends with D4D holding two tokens it didn’t have before.

Staying connected (every 6 hours, forever)

Once D4D has a refresh token, it never has to ask you to reconnect. This half runs on a timer, quietly, in the background — notice who’s missing from it.

The gotcha

Strava hands back a brand-new refresh_token on every single refresh, and the old one stops working immediately. If D4D-16 stores the token once and never overwrites it, the connection will quietly break the first time it refreshes — hours after anyone actually tested it. Whatever storage we land on has to overwrite on every refresh, not just on first connect.

What lives where

Five things, five very different lifetimes
ThingWhere it livesNotes
Client ID anywhere in the app, plain env var Public — identifies D4D to Strava. Fine to expose.
Client Secret .env.local, server-side only Gitignored, never sent to the browser. Used only in steps 6 and the refresh call.
Authorization code the callback URL’s ?code= Single-use, worthless the moment it’s exchanged.
Access token wherever we store tokens Sent as an Authorization: Bearer header. Expires in 6 hours.
Refresh token wherever we store tokens The thing D4D-16 actually needs to persist. Strava replaces it every time it’s used.

Full parameter and endpoint list: developers.strava.com/docs/authentication

Still deciding

Both diagrams above just say “save tokens” and “update store” without saying where. Real options on the table: an encrypted, httpOnly cookie (works today, no new infrastructure); a local SQLite file just for development; or treating this ticket as “get the handshake working end to end” and punting real persistence to whenever RUNFUND-26’s Postgres exists. Whichever we pick, it should live behind one small function — something like getStravaTokens() / saveStravaTokens() — so swapping the storage later doesn’t mean touching every route that needs a token.
